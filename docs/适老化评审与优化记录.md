# 人生海海 · 适老化交互评审与优化记录

日期：2026-11-15
评审对象：微信小程序「人生海海」（4 页面 + 引导页）
评审视角：中老年用户（视力退化、手指精细操作能力下降、反应变慢、对新交互模式不熟悉、怕弄坏东西）
复核：qwen4-max-preview（Token Plan）独立复核方案，补充 3 个 P0 遗漏项，已并入实施

## 一、发现的问题与处理结果

### P0 —— 阻断核心流程 / 严重可读性问题

| # | 问题 | 原状态 | 处理 |
|---|------|--------|------|
| 1 | 主色 #4A9BD1 配白字对比度仅 **3.04:1**（需 4.5:1），全站按钮/chip/年份徽章不达标 | 老花眼在户外光线下几乎看不清按钮文字 | 主色统一改为 **#24648F**（白字 6.37:1），全站 token 化 |

| 5 | 顶部按钮 top:24rpx 写死，`navigationStyle:custom` 下被状态栏压住、与微信胶囊重叠 | 刘海屏上「时间轴/云朵」点不到 | 顶部位置由 JS 按 `wx.getMenuButtonBoundingClientRect()` 动态避让；右上角不再放任何可点元素；「时间轴/云朵」移至底部 dock（88rpx 高） |

### 云端部署侧核实（2026-11-15 23:55，用开发者工具 CLI）

| 项 | 结论 |
|---|---|
| 云函数是否已上线 | `login` / `analyze` / `transcribe` 三个均 Active |
| 云端代码 vs 本地 | 下载回来 diff，**完全一致**（含 transcribe 的兜底逻辑） |
| `transcribe` 超时 | 云端 **60s**，与 `package.json` 里写的 `config.timeout: 120` **不符** |

**踩坑记录：`config.json` / `package.json` 里的 `config.timeout` 不会通过 CLI 部署生效。**
`cli cloud functions deploy` 只上传代码包，不改函数配置；CLI 也没有设置超时的参数。
超时必须在**云开发控制台手动设**。因此 `analyze` 的 60s 是当初控制台手改的，
此前没有任何文件记录，换环境重新部署会丢——现已补 `config.json` 作为意图记录。

**由此修掉一个真实缺陷（transcribe 兜底 timer 失效）：**
原代码 `totalMs = min(音频时长, 55s) + 15s`，最长 **70s > 云端 60s**，
意味着百炼服务卡住时兜底 timer 永远来不及触发，函数被平台强杀，
用户拿不到任何已识别的部分文本。已改为读 `context.getRemainingTimeInMillis()`
按平台真实剩余时间自适应（预留 5s 收尾），保证兜底一定先触发；
取不到时回落到保守的 60s 假设。

核算（60s 超时下）：录音 30s→timer 27.5s、45s→35s、55s/60s→40s，**全部早于 60s 触发** ✅
音频截断只在超时被设到 20s 这种极端值时才发生，60s/120s 下都能全量处理 55s 音频，不丢内容。

> 顺带修正两处过时注释：`transcribe/index.js` 与 `utils/asr.js` 的头部都还写着
> "协议：session.update → append → commit"，但实际实现（和第 33 行的实测注释）
> **不发 session.update**——发了反而会覆盖服务端默认转写配置导致零事件。
