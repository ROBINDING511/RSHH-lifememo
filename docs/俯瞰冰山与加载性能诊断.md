## 二、运行时性能：真问题在 Canvas，不在图片

现状 `pages/ocean/ocean.js`：Canvas 2D + `requestAnimationFrame` **常驻 60fps 每帧重绘全屏**。

每帧像素写入量（= 全屏 backing store）：

| 机型 | dpr | backing store | 60fps 重绘 = |
|---|---|---|---|
| iPhone SE | 2 | 750×1334 = 1.0M px | 60M px/s |
| iPhone SE | 3 | 1125×2001 = 2.25M px | 135M px/s |
| iPhone 15 | 2 | 786×1704 = 1.34M px | 80M px/s |
| iPhone 15 | 3 | 1179×2556 = 3.0M px | **181M px/s** |
| 安卓中端 | 3 | 1080×2340 = 2.5M px | 152M px/s |

对目标用户（中老年、大量千元安卓机）意味着：
- **CPU 永远满载**：浪、冰山摇晃、鲸鱼位移全部每帧重算重画，机身发热、掉电快；
- **低端机掉帧**：152M px/s 的写入在中端安卓上达不到 60fps，画面卡顿反而显得廉价；
- **内存**：backing store 单张 1–11.5MB（dpr3 时），叠加图片解码容易触发低端机内存警告；
- **首屏等待**：`initCanvas` 要先 `Promise.all` 加载 6 张图（冰山 5 张 330K + 鲸鱼帧 128K ≈ 460K）才画第一帧，首屏白等。

## 三、目标架构：分层 CSS 合成（零每帧 CPU）

| 层 | 内容 | 驱动方式 | CPU 占用 |
|---|---|---|---|
| 1 | 朦胧底图 soft-b5.jpg (480×850, 15KB) | 静态 background | 0（一次性解码） |
| 2 | 浪纹 tile ×2（26s / 41s 反向） | WXSS keyframes `background-position` | 合成器线程 |
| 3 | 静态大气雾霭（CSS 双渐变） | 静态 | 0 |
| 4 | 冰山群（俯瞰 PNG，各 ≤25K） | 每座一个 `wobble` keyframe（±1.2° 3-5s） | 合成器线程 |
| 5 | 鲸鱼精灵 + cruise 路径 + 转身/浮沉 | WXSS keyframes transform（GPU） | 合成器线程 |
| 6 | 飞鸟偶发横穿 | WXSS keyframes | 合成器线程 |
| 7 | UI（提示/对话泡/√✕） | 原生 view/text，随微信字体放大 | 0 |

**解码内存对比**：分层方案全部素材解码合计 **2.26MB**（底图 1.59M + 浪 0.55M + 鲸鱼 0.12M + 鸟 0.05M），
而 Canvas 方案仅 backing store 就要 **3.0–11.5MB**，且每帧 CPU 重绘。

**动画只在 transform / opacity / background-position 上**（合成器可加速属性），JS 线程在待机时**完全空闲**——这是和省电、流畅度直接相关的一点。

## 四、现有 Canvas 功能 → 分层方案的等价映射

| 现有能力（ocean.js） | 分层方案等价实现 |
|---|---|
| 相机横向平移 + 缩放（camera.x/scale 缓动） | 场景包裹层 `transform: translateX/scale` + transition；或直接省去（鸟瞰场景无需平移） |
| 手指按下鲸鱼定住（frozen） | `animation-play-state: paused` + 过渡到录音位 |
| 冰山摇曳（rotate ±0.02rad + 上下 1.5px） | 每座冰山独立 `wobble` keyframe，随机 delay 错相 |
| 浪（sin 曲线描边 ×2） | 浪纹 tile 横滚 ×2（已有） |
| 鲸鱼慢游 + 随机目标点 | cruise 关键帧路径（已有，6 帧 S 形 + rotateY 转身） |
| Canvas 触摸判定按住鲸鱼 | 底部 34% 热区 view 的 `bindtouchstart/end`（更可靠，且不依赖画布坐标换算） |

**不可迁移项核查**：录音文字、预览面板、冰山详情跳转均为原生 view，不依赖 Canvas，迁移无碍。

## 五、加载策略（首屏 & 弱网）

1. **首屏只等 1 张图**：soft-b5.jpg 15KB 即出画面；鲸鱼/浪/冰山/鸟用 `wx.getImageInfo` 后台预热，到位后淡入（opacity transition 0.4s），弱网下首屏也不白。
2. **冰山懒加载**：列表里每座冰山 `lazy-load`，屏幕外不解码。
3. **音频按需**：sea-XX.mp3（~110KB）在用户首次开启声音时才下载（`wx.downloadFile` → 本地缓存），不进首屏关键路径。
4. **分包**：packageGuide（276K）已是独立分包，不占主包首屏。

## 六、落地顺序建议

1. 素材入位：`images/ui-bg/ocean-b5.jpg`、`images/scene/{whale-top,wave-tile,bird-flap}.png|gif`、`images/scene/berg-top-*.png`、`audio/sea-XX.mp3`（从废弃目录收回 audio 目录归属）。
2. ocean.wxml 重写为 7 层结构；ocean.wxss 写全部 keyframes（参数见定稿页参数表）。
3. ocean.js 删除 Canvas 渲染循环，仅保留状态机（录音/预览/发布）与触摸事件；`onHide` 暂停动画与音频。
4. 验收：真机（含一台千元安卓）看首屏时间、待机 CPU（微信开发者工具 Audits）、连续 10 分钟耗电；跑 `node --check` 与交叉校验。
5. reduced-motion：全动画停用 + 鲸鱼/冰山静态兜底位（已验证）。
